🌉 3. DIE LOGIK DER "KNOWLEDGE BRIDGE"

Die VIRON\_KNOWLEDGE\_BRIDGE.md ist dein aktives Gedächtnis. Sie verhindert, dass du in einem Vakuum arbeitest.

Der Filter-Effekt: Die Bridge sagt dir, was physikalisch möglich ist (z.B. „Max 2GB RAM pro Thread“).

Deine Aufgabe: Wenn du in den Recherche-Daten eine Information findest, die der Bridge widerspricht (z.B. eine Empfehlung für 8K-Texturen), darfst du diese Information nicht einfach löschen. Du musst sie transplantieren, aber mit einer Warnung versehen: „ACHTUNG: Dieser Ansatz widerspricht dem Hardware-Gesetz aus Badge 7.“

Die Synchronisation: Du baust auf dem Wissen deiner Vorgänger auf. Ignoriere niemals die Bridge.

🔬 4. DAS GESETZ DES FORENSISCHEN KOPIERENS

Wenn du Code oder technische Spezifikationen aus den Quellen in den Codex überträgst, gilt die 1:1 Regel:

Imports \& Types: Jede Import-Zeile und jede Typ-Definition muss erhalten bleiben.

Kommentare: Technische Kommentare im Code sind oft wichtiger als der Code selbst. Lösche sie niemals.

Grenzwerte: Zahlen (Bitrates, Millisekunden, RAM-Werte) sind die „Smoking Guns“. Sie müssen exakt übernommen werden.

Keine Platzhalter: Die Zeichenfolge // ... ist in deinem Output strengstens verboten.

🧠 5. DER SKILL-FILTER (Vermeidung von Rauschen)

Wir haben eine Skill-Bibliothek (remotion-core/SKILL.md). Dies ist der Maßstab für „Standard-Wissen“.

Was ist Müll? Wenn eine Recherche-Datei erklärt, wie man eine React-Komponente importiert, ist das Standard-Wissen. LÖSCHE ES.

Was ist Gold? Wenn die Datei erklärt, wie man diesen Import optimiert, um das Viron-Rendering zu beschleunigen, ist das IP. BEHALTE ES.

Beweispflicht: Für alles, was du als „redundant“ verwirfst, musst du im Audit-Log die entsprechende Skill-Datei nennen.
